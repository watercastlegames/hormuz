라락 구출작전에서 났던 일이 다른 전투에도 있는지 봤다. 그 부류는 없었다. 대신 점검하다 다른 결함 두 건이 나와서 그것을 고쳤다.

찾은 것

라락에서 났던 일은 이런 것이었다 — 적을 다 잡으면 끝나는 줄 알았는데 적 전멸은 다음 단계로 넘어가는 조건일 뿐이었고, 화면은 그 다음에 뭘 해야 하는지 말해주지 않았다. 그래서 이길 수 있는 판을 5분 동안 흘려보냈다.

같은 구조가 성립하려면 승리 조건이 여러 단계여야 한다. 7종을 다 열어 보니 그런 구조는 라락과 곡괭이산 둘뿐이고, 둘 다 이미 처방이 들어가 있었다. 나머지 다섯은 승리 조건이 한 덩어리라 그 함정이 애초 만들어지지 않는다.

전부 실제로 돌려서 잰 값이다. 적을 강제로 전부 없앤 뒤 아무 명령도 주지 않고 60초 이상 지켜봤고, 자동전투만 켜고 손 놓은 경우도 따로 돌렸다.

대신 나온 것 두 건

1

화면이 알려주는 교전 시각이 실제와 달랐다

전투가 시작되면 “적이 45초 뒤 접근합니다”라고 안내한다. 그런데 그 45라는 숫자가 문장 안에 글자로 박혀 있었다. 실제 시간은 난이도에 따라 코드가 최대 12초까지 줄인다. 그래서 난이도가 조금만 올라가도 화면이 말하는 초와 실제로 적이 오는 초가 어긋났다.

기뢰 회랑은 더 나빴다. 기뢰는 계류식이라 다가오지 않는다. 실제 지연값도 0이다. 그런데 화면은 “적이 45초 뒤 접근합니다”라고 안내했다. 오지도 않을 적을 45초 기다리라고 한 셈이다.

고치기 전 · 기뢰 회랑 — “적이 45초 뒤 접근합니다. 아군을 배치하세요.”
고친 뒤 · 기뢰 회랑 — “기뢰는 이미 항로에 부설돼 있습니다. 소해 전력을 배치하십시오.”

이제 문구에는 자리만 두고 실제 값을 넣는다. 지연이 0이면 기다리라는 말 대신 다른 문장을 쓴다.

contactCountdownLine() {
  const seconds = Math.max(0, Math.round(this.config.battle.enemyEngageDelaySeconds || 0));
  if (seconds <= 0) return this.text("contactCountdownNow");
  const label = this.lang === "en" ? `${seconds} seconds` : `${seconds}초`;
  return this.text("contactCountdown").replace("{delay}", label);
}

2

대규모 함대전 브리핑이 실제 전장과 달랐다

미션 카드에 적힌 적 규모가 실제 배치와 전혀 달랐다. 없는 병종이 둘 적혀 있었고, 지켜야 할 유조선 수도 틀렸다. 이건 편성 화면 직전에 읽는 문구라, 이걸 보고 예산을 짜면 편성이 어긋난다.

고치기 전 — “고속정 48척, 지상군 12명, 발사 차량 6기를 제압하고 유조선 5척 중 최소 4척을 보호하십시오.”
고친 뒤 — “고속정 12척, 무인수상정 4척, 공중 위협 4기를 제압하고 유조선 3척 중 최소 2척을 보호하십시오.”

실제 전장에는 지상군도 발사 차량도 없다. 게다가 이 전투는 해병 편성 상한이 0이라 지상군은 넣고 싶어도 넣을 수 없다. 목표 수치도 66에서 실제값 20으로 맞췄다. 나머지 6개 미션 카드는 대조해 보니 전부 실제와 일치했다.

기뢰 회랑 — 전투 로그 첫 줄 대규모 함대전

기뢰 회랑에서는 로그 맨 위에 “기뢰는 이미 항로에 부설돼 있습니다”가 떠야 합니다. 예전 “적이 45초 뒤 접근합니다”가 보이면 캐시가 남은 것입니다.

확인 방법

7종 각각을 실제로 띄워 놓고 이렇게 확인했다.

  • 적을 강제로 전부 없앤 뒤 아무 명령도 주지 않고 60초 이상 방치 — 끝나는지
  • 자동전투만 켜고 손 놓기 — 사람 개입 없이 완주되는지
  • 단계가 있는 전투는 각 단계에서 화면 목표 줄이 지금 할 일로 바뀌는지
  • 난이도 1과 5에서 안내 문구의 숫자가 실제 값과 같은지 (한/영 각각)

기존 회귀 검사도 다시 돌렸다 — 시나리오 7종 전부 통과, 미션 라우팅 통과, 한/영 문구 사전 413키 문제 0건.

남겨둔 것
