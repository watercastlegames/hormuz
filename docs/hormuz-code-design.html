코딩 설계서 — 점수, 랭킹, 그리고 다시 하기

기획서 v0.5·화면 구성서 v1.0을 코드로 옮기는 설계. "얼마나 빨리, 얼마나 깨끗하게 전쟁을 끝냈는가"를 하나의 점수로 만들고, crimeGame에서 검증된 Firebase 구글 로그인+Firestore 랭킹을 이식하되 재시작·최고점 갱신이 가능하도록 개선한다.

SECTION 02

점수 시스템 — 빠르고 깨끗한 종전

한 줄 요약 — 최종점 = (속도 + 유가 + 지지율 + 국제지지 + 통항률 + 확전관리) × 엔딩등급 배수. 이론 최대 약 3,350점, 랭킹 정렬은 점수 → 종결일 → 통항률.

점수 구성 — 6요소 + 배수
요소공식최대설계 의도
속도(19 − 종결일) × 40600핵심 축. 협정 성립 엔딩에만 부여 (붕괴·시간초과·게임오버는 0). 룰상 최속 성립일 = DAY 4
유가 안정clamp(200 − 최종유가, 0, 130) × 3390$200(붕괴선)에서 멀수록 가점. $70 이하는 만점 처리
국내 지지율최종값 × 3300정치적 생존의 질
국제 지지최종값 × 3300혼자 이겼는가, 함께 이겼는가
통항률최종값 × 4400게임의 목표 지표 — 가중 최대
확전 관리(5 − 최고 도달 단계) × 60240이긴 방법의 대가. 시작이 LV3이므로 사실상 최대 120
엔딩 배수S+ ×1.5 · S ×1.4 · A ×1.25 · B ×1.1 · C ×1.0 · D ×0.7 · E ×0.5 · F ×0.3같은 지표라도 "어떤 역사였나"가 곱해진다

assets/js/core/scoring.js — 전문

// 점수 계산 — 이 파일이 점수의 유일한 정본이다 (UI·랭킹 모두 여기만 호출)
export const GRADE_MULT = { 'S+':1.5, 'S':1.4, 'A':1.25, 'B':1.1, 'C':1.0, 'D':0.7, 'E':0.5, 'F':0.3 };
export const NEGOTIATED = new Set(['calm_hold','short_war','hormuz_accord','uneasy_truce']); // 협정 성립 4종
const clamp = (v, lo, hi) => Math.max(lo, Math.min(hi, v));

export function computeScore(r){
  // r = { endDay, endingId, endingGrade, oil, approval, intl, transit, maxEsc }
  const speed   = NEGOTIATED.has(r.endingId) ? (19 - clamp(r.endDay, 4, 18)) * 40 : 0;
  const oil     = clamp(200 - r.oil, 0, 130) * 3;
  const appr    = clamp(r.approval, 0, 100) * 3;
  const intl    = clamp(r.intl,     0, 100) * 3;
  const transit = clamp(r.transit,  0, 100) * 4;
  const esc     = (5 - clamp(r.maxEsc, 1, 5)) * 60;
  const base    = speed + oil + appr + intl + transit + esc;
  const total   = Math.round(base * (GRADE_MULT[r.endingGrade] ?? 1));
  return { total: clamp(total, 0, 3500), parts: { speed, oil, appr, intl, transit, esc } };
}

// 랭킹 정렬 비교기 — Firestore 조회 후 클라이언트 정렬 (crimeGame 방식)
export function rankCompare(a, b){
  return (b.score - a.score)          // ① 점수 높은 쪽
      || (a.endDay - b.endDay)          // ② 빨리 끝낸 쪽
      || (b.transit - a.transit)        // ③ 해협을 더 연 쪽
      || (tsOf(a) - tsOf(b));           // ④ 먼저 기록한 쪽
}
const tsOf = r => r.updatedAt?.toMillis?.() ?? Number.MAX_SAFE_INTEGER;

SECTION 06

저장과 재시작

한 줄 요약 — localStorage 키 hormuzProgressV1 자동 저장(crimeGame notify 패턴), 재시작은 3종 — 다시 하기 / 재연 스킵 / 이어 하기.

  • 자동 저장 — patch() 호출 시마다 saveLocalProgress(). 저장 대상: state 전체(3D·UI 제외 순수 데이터). version·gameId 불일치 시 폐기(마이그레이션 없음 — crimeGame 방식).
  • 복원 sanitize — 모든 필드 화이트리스트 재검증: numberIn() clamp, phase는 VALID_PHASES 검사 후 되감기, 문자열 길이 제한. 저장값을 신뢰하지 않는다.
  • 다시 하기 — 엔딩 화면·메뉴에서 상시. resetGame({ keepUser:true }): 진행 삭제 → 새 seed 발급 → 2회차부터 재연 스킵 버튼 기본 노출(로컬 플래그 hormuzReplaySeenV1).
  • 최고 기록 보존 — 로컬 최고 기록은 별도 키 hormuzLocalBestV1 (crimeGame demoLeader 패턴) — 재시작해도 지워지지 않는다. 미로그인 유저의 "이 기기 최고 기록" 표시용.
export function resetGame({ keepUser = true } = {}){
  const user = keepUser ? state.user : null;
  clearLocalProgress();                          // hormuzProgressV1 삭제 (best는 유지)
  Object.assign(state, freshState());            // 초기값 재대입
  state.seed = (Date.now() ^ (Math.random()*1e9)) >>> 0;
  if (user) state.user = user;
  state.phase = localStorage.getItem('hormuzReplaySeenV1') ? 'TITLE_SKIP_OFFER' : 'TITLE';
  notify();
}
SECTION 07

Firebase 랭킹 — crimeGame 이식 + 최고점 갱신

한 줄 요약 — 로딩·로그인·폴백은 crimeGame 코드 그대로, 쓰기 정책만 "create 1회 불변" → "최고점일 때만 update 허용"으로 개조. 강제는 클라가 아니라 firestore.rules가 한다.

이식 그대로 (검증된 코드)

  • SDK — CDN 12.16.0 동적 import (new Function('url','return import(url)') — esbuild 번들 인라인 방지 트릭), named app 'hormuz-ranking', browserLocalPersistence.
  • 로그인 — signInWithPopup + prompt:'select_account'. 게임 플레이엔 로그인 불필요 — 엔딩 화면의 "Google로 기록 등록" 버튼에서만 로그인 발동.
  • 도메인 사전검사 — firebaseDomainAuthorized() (identitytoolkit REST로 authorizedDomains 확인) — 미승인 도메인에서 팝업 에러 내기 전에 차단.
  • 폴백 — config 미설정/네트워크 실패 시: 랭킹 버튼 숨김 + "이 기기에만 저장" 안내 + hormuzLocalBestV1 로컬 최고기록. 가짜 순위 목록은 절대 만들지 않는다(crimeGame 원칙).
  • 조회 — 컬렉션 전체 getDocs → 클라 정렬(rankCompare) → 상위 100. 소규모 랭킹판 전용 구조임을 문서화(문서 1만 건 넘으면 orderBy+limit 서버 쿼리로 전환).

assets/js/net/ranking.js — 핵심 개조부

const COLLECTION = 'hormuz_rankings_v1';
const GAME_ID    = 'hormuz-v1';

export async function saveCloudRecord(rec){          // rec = ended + dials 스냅샷
  const cloud = await runtime();
  const user  = cloud.auth.currentUser;
  if (!user) throwCode('AUTH_REQUIRED', 'Google 로그인이 필요합니다.');
  const ref = cloud.storeSdk.doc(cloud.db, COLLECTION, user.uid);
  return cloud.storeSdk.runTransaction(cloud.db, async tx => {
    const prev = await tx.get(ref);
    const payload = {
      gameId: GAME_ID,
      displayName: String(user.displayName || '익명 사령관').slice(0, 40),
      score:   int(rec.score, 0, 3500),
      endDay:  int(rec.endDay, 1, 18),
      endingId: String(rec.endingId).slice(0, 30),
      endingGrade: rec.endingGrade,             // rules에서 enum 검증
      labelId: String(rec.labelId).slice(0, 20),
      oil: int(rec.oil, 0, 400), approval: int(rec.approval, 0, 100),
      intl: int(rec.intl, 0, 100), transit: int(rec.transit, 0, 100),
      maxEsc: int(rec.maxEsc, 1, 5), seed: int(rec.seed, 0, 4294967295),
      firstAt: prev.exists() ? prev.data().firstAt : cloud.storeSdk.serverTimestamp(),
      updatedAt: cloud.storeSdk.serverTimestamp()
    };
    if (prev.exists() && int(prev.data().score,0,3500) >= payload.score){
      const e = throwable('NOT_BEST', '기존 최고 기록이 더 높습니다.');
      e.record = { id: prev.id, ...prev.data(), isMine: true };
      throw e;                                  // 쓰기 없이 종료 — UX용. 실제 방어선은 rules
    }
    tx.set(ref, payload);                        // 신규=create, 갱신=update — rules가 각각 검증
  });
}

firestore.rules — 전문

rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /hormuz_rankings_v1/{userId} {
      allow read: if true;

      function body() { return request.resource.data; }
      function validShape() {
        return body().keys().hasOnly([
            'gameId','displayName','score','endDay','endingId','endingGrade',
            'labelId','oil','approval','intl','transit','maxEsc','seed',
            'firstAt','updatedAt'])
          && body().gameId == 'hormuz-v1'
          && body().displayName is string
          && body().displayName.size() > 0 && body().displayName.size() <= 40
          && body().score is int    && body().score >= 0    && body().score <= 3500
          && body().endDay is int   && body().endDay >= 1    && body().endDay <= 18
          && body().endingGrade in ['S+','S','A','B','C','D','E','F']
          && body().oil is int      && body().oil >= 0      && body().oil <= 400
          && body().approval is int && body().approval >= 0 && body().approval <= 100
          && body().intl is int     && body().intl >= 0     && body().intl <= 100
          && body().transit is int  && body().transit >= 0  && body().transit <= 100
          && body().maxEsc is int   && body().maxEsc >= 1   && body().maxEsc <= 5
          && body().updatedAt == request.time;
      }

      allow create: if request.auth != null
        && request.auth.uid == userId
        && validShape()
        && body().firstAt == request.time;

      allow update: if request.auth != null
        && request.auth.uid == userId
        && validShape()
        && body().score > resource.data.score          // ★ 최고점 갱신만 허용
        && body().firstAt == resource.data.firstAt;    // 최초 기록 시각 불변

      allow delete: if false;
    }
  }
}

SECTION 08

랭킹 UI와 공유 카드 연동

한 줄 요약 — 엔딩 화면 = 점수 브레이크다운 + 등록 버튼 + 랭킹 100 + 공유 카드. 순위가 공유 카드에 박힌다.

  • 엔딩 화면 순서 — ① 엔딩 연출 → ② 점수 브레이크다운(6요소 막대, 카운트업 애니메이션) → ③ "Google로 공식 기록 등록" / "이 기기에만 저장" → ④ 랭킹 패널(상위 100 + 내 순위 하이라이트, isMine) → ⑤ 공유 카드 저장.
  • 공유 카드(1080×1350) — 등록 성공 시 "전 세계 N위"가 카드에 들어간다. 미등록이면 순위 없이 점수만. 파일명 hormuz_score_{score}.png.
  • NOT_BEST 처리 — "기존 최고 기록 2,431점이 더 높습니다" 토스트 + 랭킹 패널 오픈(내 기록 하이라이트) — 재도전 동기 부여 문구 포함.
  • 재시작 동선 — 랭킹 패널 하단 고정 버튼: [다시 도전하기] → resetGame() — 랭킹을 보다가 바로 재시작하는 게 핵심 리텐션 루프.
SECTION 09

치팅에 대한 솔직한 선

한 줄 요약 — 서버 없는 클라이언트 게임의 한계를 인정하고, rules 범위검증 + 이상치 차단 + 시드 공개까지만 한다.

  • rules가 막는 것: 타입·범위 위반(3,500점 초과 등), 타인 문서 쓰기, 점수 하향 조작, 삭제, 필드 추가.
  • rules가 못 막는 것: 정교하게 조작된 "그럴듯한" 점수 — 클라이언트가 점수를 계산하는 구조의 본질적 한계. 홍보용 무료 게임에서 이 이상의 방어는 비용 대비 과잉이라고 명시적으로 결정한다.
  • 완화 장치: seed 필드 공개(같은 판 재현 검증 가능), 상위권 이상치 발견 시 Firebase 콘솔 수동 삭제(운영 가이드 README에 기재), 점수 상한이 이론 최대(3,345)에 근접해 과대 조작은 자동 차단.
