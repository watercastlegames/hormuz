쓰레드·페이스북은 미리보기를 한동안 저장해 둔다. 태그를 고치면 developers.facebook.com/tools/debug 에서 다시 읽게 해야 바뀐다.

왜 문을 둘로 나누나 파일 종류가 아니라 받는 사람이 기준이다.

쓰레드 → Drive ZIP 비개발자가 많다. 받아서 바로 쓴다. GitHub은 그 자체로 "어려운 데"로 보인다. 이미 먹힌 방식을 굳이 바꾸지 않는다.
레딧·인디갤 → GitHub 개발자는 뜯어보고 고치고 물어본다. 별·포크·이슈가 남는 곳이라야 한다. Drive zip은 신뢰를 깎는다.
양쪽에 같은 파일 Drive는 터지면 할당량으로 막힌다. 그때 GitHub 링크로 갈아끼우면 된다. 그래서 둘 다 올려둔다.
영상이 증명이다 "34개 준다"는 말보다 34초 훑는 영상 하나가 빠르다. 내려도 내려도 계속 나오는 게 보여야 한다.
가이드북이 차별점 모델만 주는 곳은 많다. "어떻게 붙였는지"까지 주는 곳은 드물다. 이게 저장소를 계속 돌아보게 만든다.

바로 게시할 문구 노란 부분만 채우면 그대로 올릴 수 있다.

레딧 — r/gamedev · r/threejs

제목영어 
I open-sourced my browser-based 3D RTS — 34 production models, full source, and the integration guide
본문가로 영상 첨부 
I built a 3D real-time strategy game that runs in the browser — no framework, just vanilla JS and three.js — and I'm releasing everything.

What's in it:
- 34 production glTF models (ships, jets, helicopters, rigged soldiers with walk/combat clips) — 17.9MB total, already optimised for the web
- Multiple LOD versions of the same asset, so you can see exactly what gets dropped at distance
- Full game source (MIT), models under CC BY 4.0 — commercial use is fine
- A written guide covering what actually bit me: the LOD ladder, splitting mesh and animation across files, and which glTF optimisations silently destroy your geometry

That last one cost me a helicopter fuselage. `meshopt` on already-quantised geometry collapsed an axis to zero — and the triangle count was unchanged, so my triangle-count check passed it happily. Guard on bounding-box ratios, not triangle counts.

공개 순서 같은 날 다 뿌리지 않는다. 반응을 보고 다음을 조정한다.

순서채널올리는 것노리는 것
1일차인디게임갤플레이 링크 + GitHub가장 만만한 곳에서 반응 먼저 확인
1일차 저녁쓰레드세로 영상 + 키워드 댓글DM 전환. 팔로우 확보
2일차레딧가로 영상 + GitHub별·포크. 오래 남는 유입
인디갤을 먼저 하는 이유
반응이 빠르고 손실이 적다. 여기서 안 먹히는 문구는 레딧에서도 안 먹힌다. 첫날 반응을 보고 쓰레드·레딧 문구를 고칠 시간을 번다.

올리기 전 확인

  • 구글 지도 열쇠에 HTTP 리퍼러 제한 걸었는지 (제일 중요)
  • Drive에 ZIP 올리고 링크 있는 모든 사용자로 공유 설정
  • Drive 링크를 다른 브라우저·로그아웃 상태에서 눌러 확인
  • GitHub 저장소 만들고 release/hormuz-source/ 통째로 올리기
  • ZIP을 GitHub 릴리스에 첨부 (다운로드 수가 보인다)
  • README 첫 화면에 플레이 링크와 영상 넣기
  • 영상 3편 재생해서 끊김·오타 확인
  • 문구 안의 노란 칸 전부 채웠는지

성과는 무엇으로 보나 조회수는 참고만 한다.

쓰레드키워드 댓글 수 → DM 발송 수 → 팔로우 증가. 조회수가 높아도 댓글이 없으면 문구가 잘못된 것이다.
레딧GitHub 별 수와 릴리스 다운로드 수. 업보트보다 이게 진짜 지표다.
공통게임 플레이 유입. 모델만 받고 게임은 안 해보면 다음 글에서 게임을 앞세워야 한다.
하지 말 것
"팔로워 몇 명 되면 다음 것 공개" 같은 조건은 걸지 않는다. 조건부 이벤트처럼 보인다. 다음 공개는 날짜로 예고하고, 팔로우는 그걸 놓치지 않기 위한 자연스러운 이유로 둔다.
